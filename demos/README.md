# Demos

These demonstrations come with this project, in the order the project's install page (in the
colleague kit, its `README.md`) takes them:

1. [Diagrams in VS Code](#diagrams-in-vs-code), below — the model's diagrams in a tab of the editor:
   from a drawn element to its file in the model and back.
2. [Chat with the model](chat-with-the-model.md) — one scenario in GitHub Copilot and in Kiro: a
   question about the model, an impact question, a change proposed and rejected in the review tab,
   and the model guard that keeps the assistant's own file tools out of `model/`.
3. [Rejected changes](#rejected-changes), below — nine small edits to the model, each refused by the
   model check with the one rule it breaks.
4. [Test tables](test-tables.md) — the tables a test team verifies the architecture against, joined
   with a synthetic test team's review of last week's model, so that every review state shows:
   accepted, rejected, not reviewed, stale and an orphaned annotation. Its files are under
   `test-tables/`.
5. [The requirements exchange](requirements-exchange.md) — a walkthrough, in VS Code and on the
   command line. A synthetic requirements team delivers its requirements as a Sphinx-Needs
   `needs.json`; the architect imports them, links them to the model with the trace link search, and
   builds the architecture's own `needs.json`, which the team's Sphinx site shows beside its
   requirements, each architecture element a link into VS Code. The team's next delivery changes a
   linked requirement, and the link stays unconfirmed on both sides until the architect confirms it.
   Its files are under `requirements-exchange/`. The same exchange, told to an audience in ten
   slides (*Enrich, never change*), is
   [requirements-exchange-presentation-public.html](requirements-exchange-presentation-public.html):
   open it in a browser.

## Diagrams in VS Code

SWCraft draws the model as diagrams and writes them as files under `views/`; in VS Code they open in
a tab of the editor, where a drawn element leads to its file in the model and back. Nothing is served
and nothing listens on a port.

1. Open the project folder in VS Code. In the SWCraft panel press *Model → Diagrams*. The diagrams
   are generated and their index opens in a tab of the editor. Every later press, link and jump
   reuses that one tab.
2. In the index, open the sequence **thermal_status_display**. It walks three runnables of
   `Task_100ms` in the task's order: `ProcessDiagnosticEvent`, `ConfirmSnapshotStored`,
   `UpdateThermalStatus`.
3. **Ctrl+click** (Cmd+click on macOS) the arrow from `Task_100ms` whose label starts with
   `ConfirmSnapshotStored —` (the rest of the label is the step's note).
   `model/swc/application/DiagnosticManager.yaml` opens beside the diagram, at the runnable's own
   line (`- name: ConfirmSnapshotStored`). A plain click selects the arrow instead: the line under
   the picture names it once, beside an **Open in model** button, which does the same.
4. In that file, the line above `name: DiagnosticManager` at the top ends with `diagram` and `guide`
   (`guide` opens the guide's reference page for the file's layer; `diagram` shows the component).
   To come back to the runnable, put the cursor inside `ConfirmSnapshotStored` and choose
   **SWCraft: Show in Diagram** from the editor's context menu: the diagram comes back with
   `ConfirmSnapshotStored` selected and centred. It is drawn on this one diagram only, so nothing
   asks which.
5. **← Back** and **Forward →** in the tab's header walk the pages you opened. No key is bound to
   them.

What to know about the tab:

- **A sequence draws no calls.** `ProcessDiagnosticEvent` starts the snapshot write on `NvM` and does
  not wait for it, and `ConfirmSnapshotStored` runs when that write returns. The diagram shows both
  as steps of the task, and each step's note says what it does; the calls themselves are not drawn.
  A sequence draws the task's steps and the data the components send; the calls are in the model
  files and in `swcraft query`'s answers.
- **Saving a model file does not regenerate the diagrams.** The **Diagrams** item turns *out of date*,
  and a line at the top of the tab offers **Generate**, which runs the press.
- **Pages of another SWCraft release are not shown.** If `views/` was generated by another release,
  the tab says *These diagram pages were generated by another SWCraft release — press Generate*;
  **Generate** writes them again with the release this project runs.
- A window reload closes the tab; the next press opens it again. Outside VS Code, open
  `views/index.html` in a browser: everything but the way to and from the model files works there
  too.

## Rejected changes

A *rejected change* is a small edit to the model that breaks exactly one of SWCraft's rules. Applied
to the committed model, it makes `swcraft check-model` refuse the model and name the problem; undone,
the model is clean again. They show, on a model that otherwise uses every kind and every
field of SWCraft's model contract, that the rules
are enforced by the build and not by a reviewer's memory.

The rejected changes are data: `rejected-changes.json` holds one entry per demo — its `slug`, the `rule` it
breaks (the id of the rule in SWCraft's model contract), a `title`, an `explanation` for the
presenter, the `edits`, the `expect` lines and `errorLines`, the number of `ERROR:` lines the build
prints. An edit either replaces a `find` text, which occurs exactly once in its file, with a
`replace` text, or `create`s a file that does not exist yet. There is no script that applies them:
each one is a few lines in the editor.

### The nine demos

The "what the build says" column quotes the message of SWCraft **0.24.0**, the release these demos
were measured on. The rule id is what identifies a refusal; the wording of a message may change
between releases.

| Demo | Rule | What to change | What the build says |
|---|---|---|---|
| `incompatible-connector` | `connector.interface-mismatch` | Create `model/connectors/StateToCluster.yaml`: a connector from `VehicleStateManager.pOperatingState` to `InstrumentCluster.rThermalProtectionStatus`. | `Connector 'StateToCluster' interface mismatch: required 'IThermalProtectionStatus'` … |
| `component-below-requirement` | `safety.component-below-requirements` | In `model/swc/application/DiagnosticManager.yaml`, add the line `asil: QM` after `type: application`. | `SWC 'DiagnosticManager' declares ASIL QM, below the ASIL A` … |
| `consumer-without-measure` | `safety.consumer-above-element` | In `model/swc/application/BrakeThermalProtection.yaml`, delete the `measures:` key of port `rOperatingState` and its two entries (`state`, `vehicleSpeed`). | `SWC 'BrakeThermalProtection' (ASIL B) requires 'state' (ASIL QM) through port 'rOperatingState'` … — and the same line for `vehicleSpeed` |
| `partition-on-unqualified-core` | `safety.partition-on-unqualified-core` | In `model/hardware/P_Brake.yaml`, change `core: Core1` to `core: Core0`. | `Partition 'P_Brake' (ASIL B) is on core 'Core0' (ASIL capability A): a partition placed on a core not declared able to host its level.` |
| `period-not-multiple` | `task.runnable-period-not-multiple` | In `model/swc/application/BrakeController.yaml`, change `period: 0.05` to `period: 0.04`. | … `runnable 'BrakeController.ProcessBrakeRequest' has timing period 0.04s` … |
| `ram-over-budget` | `hardware.threshold-breach` | In `model/swc/application/BrakeThermalProtection.yaml`, change `RAM: 4096` to `RAM: 16000`. | `Memory 'RAM' consumption 26240 bytes exceeds its budget of 24576 bytes` … |
| `unmapped-enum` | `data-type.application-type-unmapped` | In `model/swc/application/BrakeController.yaml`, delete the two lines `data_type_mappings:` and `- BrakeThermalMappings`. | `SWC 'BrakeController' speaks type 'ThermalProtectionState' on its ports` … |
| `queued-implicit-read` | `swc.access.queued-implicit-read` | In `model/swc/application/DiagnosticManager.yaml`, add the line `by: implicit` under the read of `rThermalProtectionEvent.event` (after `element: event` in `reads:`). | `SWC 'DiagnosticManager' runnable 'ProcessDiagnosticEvent' reads queued data element 'event' through port 'rThermalProtectionEvent' implicitly` … |
| `implicit-read-with-update-flag` | `swc.access.implicit-read-enable-update` | In `model/swc/application/BrakeThermalProtection.yaml`, change the read `R_BrakeTemperature`'s `by: value` to `by: implicit`. | `SWC 'BrakeThermalProtection' runnable 'EvaluateThermalProtection' reads data element 'temperature' through port 'rBrakeTemperature' implicitly` … |

The exact `find` and `replace` texts are in `rejected-changes.json`.

### How to apply one

1. Open the project folder in VS Code.
2. Make the one change the table names, in the file it names, and save.
3. In a terminal opened in the project folder, run

   ```text
   swcraft check-model --project swcraft.yaml
   ```

   It exits with a failure and prints `ERROR:` lines naming the problem. On the committed model the
   same command prints `Validation passed (no artifacts generated).` The panel's *Model → Check
   Model* runs the same check.

Every refusal shown here is `check-model`'s. It reads the model and writes nothing, so a demo leaves
no file behind except the edit itself.

### How to undo one

**In the repository**, discard the one edit with git, naming the file the demo changed — for
example, for `partition-on-unqualified-core`:

```text
git checkout -- model/hardware/P_Brake.yaml
```

The one demo that creates a file, `incompatible-connector`, is undone by deleting that file,
`model/connectors/StateToCluster.yaml`.

To undo every demo at once there are two lines — separate, so that any shell runs them, PowerShell
5.1 included:

```text
git checkout -- model
git clean -fd model
```

**They throw away all uncommitted work under `model/`**, not only the demos': the first restores
every changed model file, the second deletes every untracked file there. Commit or stash your own
model changes first, and run `git clean -nd model` to list what the second line would delete.

**In an unpacked kit**, where there is no git: undo the edit in the editor and save, or unpack the
kit's zip again.
